# ZMR-04 H1 recall-safe hierarchy: public development disposition

The frozen H1 v0.1 cohort contains 60 candidate-writer rows: 36 single intent across all 18 Catalog domains, 12 no-request controls, six context-required rows and six two-goal rows. It was frozen before any H1 Router output. This is `NON_INDEPENDENT_DEVELOPMENT_EVIDENCE` with zero independent ZMR-01B quota. The original frozen cohort file remains marked `UNRUN` as an intake artifact; the separate once-written result files record subsequent consumption.

The initial H1 mechanism grouped full144 A2 Topic scores into domains and added a bounded domain score only when the A2 Topic's domain was in the top three. The full144 A2 route always remained available. It ranked the correct domain first on 17/36 single rows and within the top three on 22/36. A2 with the same explicit no-request scope guard achieved 12/48 provisional labeled exact sets with 17 assignments and one false assignment among 12 controls. H1 produced **identical Topic outputs**: no exact gain, no loss, no topic switch and no avoided false control assignment. Context-required exact was 1/6; multi exact was 0/6. The first one-shot public diagnostic is `ZMR-04_H1_RECALL_DEV_V01_RESULT.json`.

One bounded mechanism repair compiled a separate 18-domain sparse likelihood index from the pinned 144-Topic Catalog and fixed public TRAIN v0.2. This is a different coarse evidence source from grouping A2 Topic scores, not a parameter sweep. It maintains all 18×8 Topic closure and never permanently excludes a Topic. A fixed top-three rank prior was applied only when the full144 flat assignment was already within those domains; otherwise the flat output was recovered. The repaired domain index was 130,320 bytes and the A2 index 206,821 bytes. The combined static runtime-plus-index count was 370,400 bytes, within the hard byte caps; browser latency and memory were **not** measured or qualified.

The reused, exposed public DEV inner-loop result is `ZMR-04_H1_R1_RECALL_DEV_V01_RESULT.json`. Correct domain top-three retention became 25/36, while top-one was 13/36. Two assigned A2 Topics lay outside the coarse top three and were recovered through the flat path. Topic output still matched A2+scope on every row: zero exact gains, losses, topic switches and avoided false control assignments. The remaining 1/12 control false rate and 1/6 context and 0/6 multi exact counts remain far from the unchanged gates. Deterministic repeats showed zero differences. The public DEV was reused for repair diagnosis, **not** a fresh challenge or independent gate.

H1 is retired from the active architecture path after one bounded mechanism repair because neither version contributes isolated end-to-end gain over the simpler full144 flat anchor. There is no reason to spend the optional second repair or freeze a new H1 challenge for this unchanged-output mechanism. The compiler and Router are retained only as reproducible development evidence, not selected runtime components. This does not establish a hierarchy-family or zero-model ceiling. The next development hypothesis should use the canonical A5/A6 finite structure and source-separated per-goal evidence with a genuinely different chart-like evidence aggregation, and must freeze a new public cohort before candidate outputs. Earlier consumed public keys, sealed AS, final TEST and CIG-v1 TEST remain untouched. Capability is `UNTESTED`, resource is `NOT_QUALIFIED`, and ZMR-01B independent data remains `NOT_QUALIFIED`.
