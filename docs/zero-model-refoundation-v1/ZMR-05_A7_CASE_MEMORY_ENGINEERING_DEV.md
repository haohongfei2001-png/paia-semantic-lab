# ZMR-05 next development hypothesis: bounded A7 case memory

C1 and its first mechanism repair were rejected on fresh public same-writer evidence. Their continuation grammar and separate recent-text scorer did not produce an exact context-required or multi-intent result, while unsafe controls remained far above the fixed gate. The component is retired without a family ceiling claim. A7 is a different **base evidence aggregation** hypothesis drawn from the finite case-memory option in `ARCHITECTURE_CANDIDATES`: preserve a bounded set of individual TRAIN scenarios for each of all 144 Topics and score the maximum supported scenario match. A1 collapsed all evidence for each Topic into one class document; A3 learned one-vs-rest weights; C1 manipulated current/recent context on top of A3. Per-scenario maximum is a distinct, testable aggregation from those specific implementations, though it does not earn a separate saturation-family count without independent comparison.

The engineering module accepts two to eight provenance-identified TRAIN scenarios per Topic, requires unique source and scenario lineage, compiles deterministic bounded character/word n-gram TF-IDF vectors and caps each prototype at 48 features. The index contains feature weights and lineage IDs, with no raw sentence field; n-grams may reveal portions of public TRAIN text and are not a privacy boundary. It enforces the unchanged 1 MiB static index cap and always retains a full144 Topic universe. Current-only routing compares the input with each finite prototype, takes the best supported scenario per Topic, then uses fixed score, margin and matched-feature requirements to ASSIGN one Topic or DEFER. Title and recent text cannot independently affect this base candidate; context and explicit multi-intent remain unsolved and require separate evidence. No neural asset, embedding, LLM, semantic API or network fallback is introduced.

Three synthetic-index tests cover deterministic compilation despite input order, two different scenario paths to the same Topic, complete Topic universe, static byte cap, current-only invariance and fail-closed lineage/Catalog/input/index/configuration behavior. They are pure engineering evidence. The candidate has **no** real TRAIN build, semantic evaluation, browser memory/latency receipt, independent review or capability promotion. Its 8,192-scalar/32-recent-entry input boundary is a research measurement profile, not a production truncation policy. Static index budget passing on synthetic cases cannot establish resource PASS.
