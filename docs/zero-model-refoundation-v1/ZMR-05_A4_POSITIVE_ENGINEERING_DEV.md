# ZMR-05 A4 bounded positive-evidence pairwise resolver — engineering only

This is a distinct development mechanism after the A4 negative-evidence veto and A5 standalone composition paths were retired. It reuses the pinned 144-Topic Catalog, the Catalog-derived provisional graph, the **designated public A4 TRAIN v0.1** and the full144 A3 char fallback compiled from public TRAIN v0.2. The existing fixed compiler produces four rank-registered pair feature lists from two provisional positive examples per side while excluding opposite-side and unresolved ambiguous TRAIN terms. The ambiguous cases have **no gold** and are not taught as DEFER labels. No consumed challenge, AS, final TEST or CIG-v1 TEST enters the compilation closure.

The new Router validates the full144 index and four fixed graph pairs, then routes the original `current` with A3. It can change an A3 assignment **only** when that assignment is already one member of a registered pair and at least three exclusive opposite-side TRAIN n-grams are present, no own-side n-gram is present, and the support margin is at least two. It assigns the opposite member with the exact pair rank and support counts recorded. Conflicting side evidence DEFERs. An A3 DEFER, a Topic outside the four pairs, weak pair evidence and title/recent text cannot create a new assignment. Bad closure or configuration fails closed. This is a positive contrastive correction; unlike the retired veto it can switch a label, so fresh paired challenge data must measure new wrong assignments and lost correct outputs.

Three synthetic/integration engineering tests cover an exclusive positive switch, conflict and bad closure, unchanged full144 fallback, and construction from the fixed public TRAIN-only compiler. The complete ZMR package suite has 93 tests in this batch. The A3 char and pair indexes total 123,866 bytes; A1+A3+new positive Router source totals 17,790 bytes, or 141,656 combined. These static counts fit the unchanged 1 MiB index and 2 MiB combined caps. Browser bundle, warm p95, cold initialization and incremental memory have **not** been measured, so resource verdict remains `NOT_QUALIFIED`.

The original provisional boundary graph remains a Catalog hypothesis with no independently validated resolver.
